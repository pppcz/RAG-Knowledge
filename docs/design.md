# 设计方案

本文记录项目的设计目标、关键取舍与边界，架构图与模块划分见
[architecture.md](architecture.md)，表结构与索引选型见 [database.md](database.md)。

## 1. 设计目标

1. **能独立跑通**：不依赖任何付费服务，`docker compose up -d --build` 后即可注册、登录、
   建知识库、传文档、提问并拿到带引用的流式回答。
2. **可切换到真实模型**：LLM 与 Embedding 都通过配置切换，业务代码零改动。
3. **多租户隔离**：数据按租户隔离，权限粒度到接口。
4. **可复现**：Python 版本、依赖、数据库结构都由锁文件与迁移固定。
5. **可部署**：单机 Docker 部署，不引入 K8s 等额外复杂度。

## 2. 总体思路

```text
上传 → 解析 → 切片 → 向量化 → 入库(pgvector)
提问 → 向量检索 top_k → 拼装上下文 → 流式生成 → 带引用返回
```

关系数据与向量同库存储，避免再维护一套向量数据库；检索与小规模写入都在单机 PostgreSQL
内完成，事务边界清晰。

## 3. 关键决策与取舍

| 决策 | 取舍理由 |
| --- | --- |
| Python 3.12 + uv | 依赖与解释器版本都能锁定，构建可复现；3.12 的异步与类型生态成熟 |
| PostgreSQL + pgvector 同库 | 元数据、切片、向量在一处，省掉跨库同步；代价是向量检索规模受单机限制 |
| 向量索引用 HNSW | 空表即可建索引、插入即时生效，适合从零积累的知识库；代价是内存占用与构建时间高于 IVFFlat |
| 端口用 5433 而非 5432 | 常见开发机上已有本地 PostgreSQL 占用 5432，避开可让 compose 直接起来，无需改系统服务 |
| LLM 默认 mock | 免费模型限流严格（约 20 次/分、50 次/天），无 Key 或限流时若直接报错会阻断演示；mock 保证链路可用 |
| Embedding 默认 hash | 本地确定性哈希，零依赖零成本，能捕捉词汇重叠；语义质量不足时切换真实模型并重建向量 |
| SSE 而非 WebSocket | 问答是单向流式，SSE 用普通 HTTP 即可，Nginx 反代只需关闭缓冲 |
| 文档上传后同步索引 | 规模小，省掉任务队列；解析失败只置 `failed` 并保留重试入口 `reindex` |
| Redis 只预留 | 当前单机规模不需要缓存与限流，先接入但不阻塞主流程 |

## 4. 降级策略

外部依赖失效时，功能降级而不是报错退出：

- LLM 无 Key、限流或网络异常 → 首个 token 前切换到 `mock`，流不中断
- Embedding 无 Key → 使用 `hash`
- MinIO 不可用 → 可切 `STORAGE_PROVIDER=local` 写入本地目录
- Redis 不可用 → 不影响登录与问答（当前未做硬依赖）

降级全部通过 `.env` 开关控制，代码里不写死。`GET /health` 不依赖任何外部服务。

## 5. 数据与权限模型

- 租户是一切数据的边界：`users`、`roles`、`knowledge_bases`、`documents`、`chunks` 都带 `tenant_id`
- 权限码形如 `kb:read`、`docs:write`、`chat:ask`，通过角色聚合到用户
- 会话与消息挂在租户与用户下，历史记录按用户可见范围过滤

## 6. 明确不做的事

- 不做跨租户共享知识库
- 不做文档在线预览与协同编辑
- 不做多机集群与分布式向量库
- 不做前端组件级单测（依赖后端 pytest 与联调验证）
